# 어드민 목업 UI/UX 기준

기획 IA·기능정의 시트로 어드민 목업을 만들 때 따르는 기준. 세부 규칙의 정본은 아래 문서들이며, 이 문서는 요약과 확정 결정을 모은다.
판단이 애매하면 세션 "UI/UX 기초 자료 구축"에 확인 요청한다.

## 0. 정본
- 저장소 hyundaiezwel/ezwel-admin-ui-ux-guide, 배포 https://hyundaiezwel.github.io/ezwel-admin-ui-ux-guide/
- 먼저 읽기: [ui-conventions.md](ui-conventions.md)(UI-nn) → [patterns.md](patterns.md) → [accessibility.md](accessibility.md) → [lessons-from-audits.md](lessons-from-audits.md). 상태 규칙 예시 [state-rules.md](state-rules.md)
- 본보기 화면: `src/pages/sp/*` (목록·상세·`UploadPage`·`BulkCancelPage`·`NoticeEditPage`)
- 새 컴포넌트 전에 `src/ws/*`, `src/app/*` 검색. `ws-*` 클래스는 예약어 — 화면에서 재정의 금지(UI-30)
- 완료 조건: `check:ui` · `check:responsive`(1280/1024/640) · 대비 검사 · typecheck · test · build 통과

## 1. 기반 값
- 글꼴 Inter + Noto Sans KR. 토큰 `--ws-*`(라이트·다크). 임의 px 금지
- 여백 사다리(UI-35): 붙은 것 4(`--ws-gap-adjacent`) · 줄 사이 6(`-item`) · 그룹 안(라벨–입력) 8(`-intra`) · 제목줄 → 내용 12(`-inter`) · 그룹 사이 16(`-block`) · 영역 사이 24(`-region`). 이 여섯만 쓰고 2px은 테두리 전용 `--ws-space-hair`. **그룹 사이 ≥ 그룹 안 × 2**, 헷갈리면 큰 쪽. 카드 패딩은 `--ws-card-pad`
- 버튼 높이 32 · 24 두 가지, 모서리 `--ws-radius` 하나(알약 없음). 글자 12 · 13 · 14 · 16 · 20, 요약 숫자 22(`--ws-font-kpi`)
- 화면 폭(UI-10): 권장 1280. **640px(200% 확대)까지 화면 전체 가로 스크롤 없음** — 틀에 최소 폭을 두지 않고, 넓은 표만 그 안에서 스크롤. 1280 미만 사이드바 레일(64) 자동, 페이지 좌우 여백 48→24. 모바일 지원(터치 · 모바일 전용 배치)은 대상 아님
- 한글 `word-break: keep-all`. 좁아지면 쪼개지 말고 줄바꿈·쌓기·스크롤

## 2. 셸 (확정)
- 사이드바 240 / 레일 64, 행 40, 아이콘 상자 20. 활성 = 배경 + 글자 + 좌측 3px 막대. 스크롤은 주 메뉴 구역만
- 최상단 '지원 사업 관리' 아이콘 자리에 파비콘(쉼표 A안) 기호. 관리자 센터 폐기 — 지원 사업 관리로 흡수
- 상단바 A안. 접는 순서: 1280 미만 칩 글자 → 1152 미만 검색 돋보기·테마 버튼 숨김 → 1024 미만 서비스명. 알림·아바타는 유지
- 탭: H-PMS 1차 탭 모양, 폭 176 고정, 말줄임 + `title`. 경로 단위, 닫으면 왼쪽 탭, 첫 화면 탭 고정. 미저장 화면은 닫기 확인(`tabs.ts` leaveGuards) + `beforeunload`
- 스크롤바: 트랙 투명 + 얇은 둥근 손잡이(`--ws-scroll-thumb`). 탭바는 숨김

## 3. 입력 칸 (확정)
- 라이트: 채움 없음(테두리만). 다크: F2 채움. 그림자 없음
- 셀렉트·데이트피커는 꺾쇠/달력 아이콘으로 식별
- 필수: 라벨 옆 `*` + 스크린리더 "(필수)". 오류는 필드 아래 `role="alert"`, 색만으로 표시 금지
- 읽기 전용은 `readonly` + 회색 바탕(`disabled` 아님). `maxlength` + 남은 글자 수

## 4. 화면 유형
- **목록**: 제목 → (권한 안내 한 줄 `.ws-pgt-note`) → `WsSearch`(UI-01, 제목 '조회', 오른쪽 초기화 아이콘 + 조회(F2)) → (합계 `.ws-sum`) → 제목줄(건수·단위·버튼) → 그리드 → `WsPager`(0건이면 안 보임)
  - 조회 영역(UI-02 · UI-13): 이름 왼쪽(열마다 가장 긴 이름, 최대 112 · 오른쪽 맞춤) · 같은 폭 칸 한 줄 3칸 → 2칸 → 1칸. 입력칸 폭은 보통 · 길게(`colspan="3"`) · 짧게(`.ws-sh__s`)만. 인라인 width 금지, 검색어 구분+입력은 앞머리형 한 칸 `.ws-kw`. 상세조회 접기는 항목 6개 초과만
  - 안내문은 대상 옆(UI-32): 조건 설명은 그 칸 아래, 단위는 표 제목 옆 「단위: 원」, 항목 뜻은 표 머리 「?」, 권한은 제목 아래. 목록 맨 아래에 모으지 않는다
  - 합계는 회색 카드 `.ws-sum` 한 모양(UI-33). 대시보드 · 통계는 흰 카드 `.ws-card`
  - 참여년도·사업은 상단바 전역 조건(UI-03). '전체' 값 `'ALL'`(UI-04). 기간 `WsPeriod`(UI-05)
  - 빈 상태 "조회 결과가 없습니다."(`QueryState`), 조회 실패 인라인, 로딩은 표 자리 스켈레톤
  - 제목 링크 한 줄 말줄임 + `title`, 배지 `flex:none`, td/th에 `display:flex` 금지
- **상세/등록**: `.ws-tb` 입력 표(라벨 칸 160). 짧은 폼(모달)은 `.ws-form`. 저장은 오른쪽, 삭제를 저장 옆에 두지 않음
- **일괄 처리**: `WsStepTrack` → 조건 표 → 양식 내려받기 → `WsUpload` → 행별 검증 결과 → 하단 가운데 실행 + 확인 모달 → 안내(UI-17). 전건 검증 후 일괄, 부분 저장 없음
- **팝업**: 목록 보며 편집 = Drawer, 확인·경고·짧은 입력 = `WsActionDialog`. 배경 클릭으로 안 닫음, Esc는 맨 위 하나만. 확인 문구는 결과를 적는다("3건을 삭제합니다. 되돌릴 수 없습니다."). 실행 버튼은 하는 일 이름(「삭제」 「파기」), 취소 동작이면 닫기는 「취소하지 않음」(UI-34)
- **서식 본문**: `WsEditor`(Tiptap). 허용 태그·스타일은 `src/ws/editor-schema.ts`만

## 5. 상태·문구
- 상태 라벨·배지 색은 한 곳(`src/sp/status.ts`, `src/ws/badge.ts`). 하드코딩 금지
- 영역마다 주 버튼 하나. 선택지 3개 초과 셀렉트, 10개 초과 검색
- 문구(UI-34): 요청은 「~해 주세요」, 결과 없음은 「조회 결과가 없습니다.」 하나
- 오류 위치: 항목 검증 필드 아래 / 목록 조회 인라인 / 저장·삭제 토스트 / 권한 없음 버튼 숨김·비활성 / 세션 만료 모달

## 6. 목업 작업 규칙
- 시트의 메뉴명·화면명 그대로. 시트에 없는 업무 규칙은 `가정` 표시 + 확인 목록
- 목업 데이터는 `MOCK(...)` 주석으로 구분
- 공개 저장소 — 고객사·사업 실명 등 비공개 식별자 금지, 푸시 전 `git grep` 0건 확인
- 리뷰 다섯 질문: 어느 역할 토큰인가 · 그룹 사이가 그룹 안 2배인가 · 흑백으로도 위계가 서는가 · 주 버튼 하나인가 · 빈·오류·로딩을 그렸는가

## 확인 요청 형식
